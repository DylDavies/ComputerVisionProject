\needspace{8\baselineskip}\section{Summary}

We trained a face recognition network from scratch (the \textbf{surrogate}) and used projected gradient descent (PGD) against it to edit one photo in each of the 3,000 same-person pairs of the LFW View 2 benchmark. We then asked four models that were never used while editing whether they still recognise the pair as the same person.


\textbf{Main finding.} The edits work almost perfectly on the model they were built against and transfer poorly to everything else. At an edit budget of $\varepsilon$ = 4/255, where the edited photo is still nearly identical to the original (SSIM 0.955), the surrogate stops matching 99.9\% of same-person pairs, but the other deep models lose only 6.3\% (casia), 1.7\% (vggface2) and 0.4\% (arcface). Random noise at the same budget does almost nothing to any deep model, so the effect comes from the optimisation, not from changing pixels. Repeating the sweep with two more random seeds changes no result by more than 0.75 percentage points (standard deviation).


\textbf{Is it just our surrogate?} To check, we repeated the attack using each pretrained deep model as the attacker (Section 9). Our surrogate turns out to be the \emph{weakest} attacker of the four: at $\varepsilon$ = 8/255 its edits make casia lose 20.6\% of pairs, while edits built against vggface2 make casia lose 82.2\%. Edits transfer well \textbf{within the same architecture} (the three InceptionResnetV1 models) even when the training faces differ, while ArcFace, a different architecture, resists edits from every attacker (at most 18.8\%, even at a visible $\varepsilon$ = 16/255). So on the proposal's second question, the evidence points to \textbf{architecture} more than training data, and how well protection transfers depends heavily on which model the edit was built against.


\needspace{8\baselineskip}\section{Context: the question and why it matters}

Privacy tools such as Fawkes and LowKey add small, hard-to-see edits to photos before they are posted, so that face recognition systems can no longer link them to the person. These tools assume an edit built against one recognition system will also defeat whatever system someone else is running. A photo is edited once and must then hold up against every system that sees it later, so if edits do not \emph{transfer}, the protection is much weaker than it looks.


Our proposal asked two things: (1) when we edit a photo until \emph{our} model stops recognising it, do models we had no access to also stop recognising it? (2) Where some models resist and others give way, is that explained by their architecture or by the faces they were trained on? The four test models were chosen so that each differs from the surrogate in a controlled way.

\needspace{6\baselineskip}\subsection{Data}

\textbf{Test data:} LFW View 2, the standard benchmark of 6,000 fixed pairs (3,000 same-person, 3,000 different-person) split into 10 folds, covering 7,701 distinct photos. We use the published pairs unchanged, including the six known mislabelled pairs, as the maintainers request. The MTCNN face detector found a face in all 7,701 photos.


\textbf{Surrogate training data:} CASIA-WebFace, 465,498 images of 10,072 people, already aligned to 112$\times$112 pixels. LFW is too small to train on, so a separate dataset is needed; using CASIA means the surrogate shares its training faces with the casia test model, which is what lets us separate the effect of data from the effect of architecture.


\needspace{6\baselineskip}\subsection{How each model sees a photo}

Every edit is made on the full 250$\times$250 LFW photo, exactly as a user would post it. Each model then crops and aligns that same photo its own way, so every model sees the same edit:


\begin{itemize}
  \item  \textbf{vggface2 / casia:} a box crop around the detected face, 32-pixel margin, resized to 160$\times$160 (margin chosen by validation, Section 4).
  \item  \textbf{arcface / lbph:} the official InsightFace 5-point alignment to 112$\times$112 (eyes, nose, mouth corners).
  \item  \textbf{surrogate:} 5-point alignment to 160$\times$160, using landmark positions measured on the CASIA training crops, so its LFW test faces line up the way its training faces do.
\end{itemize}

All crops are implemented as one differentiable warp, so the surrogate's own cropping is part of the PGD optimisation. Face landmarks are detected once on the clean photo and reused for its edited versions.


\needspace{6\baselineskip}\subsection{Deciding ``same person''}

Each model turns a photo into an embedding and compares two photos by a distance (cosine distance for the deep models, chi-square for LBPH). A pair counts as the same person if the distance is below a threshold. Following the standard LFW protocol, each model gets its own threshold for each fold, fitted on the clean pairs of the other nine folds. These clean-data thresholds are then kept fixed when scoring edited photos, so a model's error rate at $\varepsilon$ = 0 is its ordinary baseline error.


\needspace{6\baselineskip}\subsection{The edit (PGD) and the comparisons}

PGD repeatedly nudges every pixel in the direction that makes the surrogate see the edited photo as \emph{more different from its own original}, then pulls any pixel that has moved further than $\varepsilon$ back within that limit. We push away from the photo's own original rather than from its pair partner because a real user does not know which photo their posted image will be compared against. Settings: $L_\infty$ budget $\varepsilon$, 20 steps, step size 2.5$\varepsilon$/20, random start. Edited photos are rounded back to ordinary 8-bit images before scoring.

\needspace{8\baselineskip}\section{Training the surrogate}

The surrogate is an InceptionResnetV1 trained from random initialisation for 30 epochs on CASIA-WebFace (1,818 steps of 256 images per epoch), using softmax cross-entropy over the 10,072 identities, SGD with Nesterov momentum 0.9, weight decay 5e-4, a one-cycle learning-rate schedule peaking at 0.1, bf16 mixed precision and random horizontal flips. Using the same architecture and objective as the facenet test models is deliberate, so that the casia model differs from the surrogate only in its random starting weights. Training took about 1.5 hours on an RTX 5070 Ti.


500 CASIA identities were held out of training and used as a validation set (fixed same-person and different-person pairs). After each epoch the network was scored on those pairs and on clean LFW View 2 (10-fold protocol). The saved model is the epoch with the best held-out accuracy (epoch 27); LFW played no part in the choice.

\needspace{6\baselineskip}\subsection{What the numbers say}

\textbf{The edit works on the model it was built against, and quickly.} The surrogate goes from a 2.0\% baseline to 14.6\% at $\varepsilon$ = 1/255, 75.1\% at 2/255 and 99.9\% from 4/255 upward. At 2/255 the edit is essentially invisible (SSIM 0.986).


\textbf{The edit barely transfers at invisible budgets.} At $\varepsilon$ = 4/255 (SSIM 0.955), every test deep model stays within a few points of its baseline: casia 1.8\% $\to$ 6.3\%, vggface2 0.8\% $\to$ 1.7\%, arcface 0.3\% $\to$ 0.4\%. A photo that is fully protected against the surrogate is still recognised by every other deep model about 95\% of the time or more.


\textbf{With our surrogate as attacker, shared training data looks decisive.} casia and vggface2 have the same architecture and objective; the only difference is that casia was trained on the same faces as the surrogate. At $\varepsilon$ = 16/255 casia loses 60.7\% of pairs while vggface2 loses 14.6\%, about four times less (at $\varepsilon$ = 8/255: 20.6\% vs 3.5\%). Changing architecture, objective and data together (arcface) removes transfer almost entirely: 1.0\% at $\varepsilon$ = 16/255. \emph{Section 9 shows this reading does not hold once other models are used as the attacker.}


\textbf{Visible edits are needed before anything transfers.} The only substantial transfer (casia, 60.7\%) happens at $\varepsilon$ = 16/255, where SSIM has dropped to 0.659 and the edit is clearly visible. So in our setting, an edit that is invisible is not transferable, and an edit that transfers is not invisible.

\needspace{6\baselineskip}\subsection{What changes}

\textbf{Our surrogate is the weakest attacker.} At $\varepsilon$ = 8/255 its edits make casia lose 20.6\% and vggface2 3.5\%. Edits built against vggface2 make casia lose 82.2\%; edits built against casia make vggface2 lose 32.0\%. So the low transfer in Section 6 is partly a property of our surrogate, and ``edits barely transfer'' was too strong as a general statement.


\textbf{But it is not a broken model; it is an easy target.} Edits from casia and vggface2 make the surrogate lose 81.2\% and 72.0\% of pairs at $\varepsilon$ = 8/255, and 27.1\% and 19.4\% at $\varepsilon$ = 4/255. It is fragile, and its own gradients point in directions the other models do not share.


\textbf{Architecture matters more than training data.} The three InceptionResnetV1 models fool each other well even when their training faces differ: vggface2 $\to$ casia is 82.2\% at $\varepsilon$ = 8/255 and 98.7\% at 16/255. ArcFace, the only different architecture, resists every attacker: the best is vggface2 at 18.8\%, and only at a clearly visible $\varepsilon$ = 16/255. In the other direction, ArcFace's own edits reach the InceptionResnetV1 models only moderately (55.3\% surrogate, 45.9\% casia, 21.4\% vggface2 at $\varepsilon$ = 16/255).


\textbf{Transfer is lopsided.} vggface2 $\to$ casia (82.2\% at $\varepsilon$ = 8/255) is much stronger than casia $\to$ vggface2 (32.0\%). The model trained on the larger, more varied VGGFace2 data is both the strongest attacker and the hardest InceptionResnetV1 model to fool.


\textbf{Invisible edits still transfer only partially.} At $\varepsilon$ = 4/255 (SSIM about 0.95) the strongest transfer between any two different deep models is casia $\to$ surrogate at 27.1\%; at $\varepsilon$ = 2/255 nothing transfers above 5.1\%. JPEG after editing reduces transfer slightly (e.g. vggface2 $\to$ casia 82.2\% $\to$ 74.7\% at $\varepsilon$ = 8/255).


\textbf{LBPH} sits at 42.6\%--46.5\% at $\varepsilon$ = 8/255 whichever model built the edit, which supports treating it as noise-sensitive rather than fooled (Section 10).


\textbf{Why might our surrogate be a weak attacker?} These are untested hypotheses: (1) \emph{overfitting}: training accuracy reached 97.6\% while LFW accuracy plateaued, although we kept the epoch that was best on held-out identities; (2) \emph{crop geometry}: the surrogate aligns faces by landmarks, while casia and vggface2 use a box crop, so edits shaped through one geometry may carry over worse to the other (ArcFace, which also uses landmark alignment, transfers better to the surrogate, 24.1\%, than to casia, 16.3\%, at $\varepsilon$ = 8/255); (3) \emph{training budget}: 30 epochs on CASIA alone, much less than the pretrained models received.

Our surrogate's edit looks like unstructured texture with little facial structure. This is a plausible visual explanation for why its edits transfer so poorly (Section 9.1), though we have not tested it formally.
  \item  \textbf{Each edit stays inside its attacker's crop.} PGD can only change pixels the attacker actually looks at, so each edit is a rectangle matching that model's crop: a landmark-aligned square for the surrogate and arcface, the MTCNN box with margin for casia and vggface2. An edit built through one crop may miss part of another model's crop.
  \item  \textbf{The rest is PGD's random start.} Outside the crop, the speckle is the random starting noise, which no gradient ever updates. It is the same for every attacker and slightly lowers SSIM; it is not part of the optimised edit.
\end{itemize}

\needspace{8\baselineskip}\section{A note on LBPH (the non-deep model)}

LBPH needs careful interpretation. Its clean accuracy is only 67.0\%, so with its best threshold it already fails to match 47.2\% of same-person pairs before any edit. Its numbers also move in the opposite direction from what transfer would predict: small PGD edits slightly \emph{lower} its unmatched share (47.2\% $\to$ 39.0\% at $\varepsilon$ = 4/255), random noise affects it far more than PGD at $\varepsilon$ = 16/255 (90.1\% vs 65.6\%), and blur at $\sigma$ = 3 breaks it almost completely (99.6\%).


LBPH describes faces by fine local texture, so any change to pixel-level texture moves its distances, whether or not the change is targeted. Its numbers therefore measure sensitivity to pixel changes in general, not transfer of the edit, and it should be reported as a non-deep baseline rather than as evidence that the edit transfers.


\needspace{8\baselineskip}\section{Conclusions}

1. \textbf{Edits built against our surrogate transfer poorly.} A nearly invisible edit ($\varepsilon$ = 4/255) that fully defeats the surrogate leaves every other deep model recognising about 95\% or more of the same-person pairs.


2. \textbf{The results are stable.} Across three random seeds no result's standard deviation exceeds 0.75 percentage points.


3. \textbf{Transfer depends strongly on which model the edit is built against.} Our surrogate is the weakest of four attackers: edits built against vggface2 make casia lose 82.2\% of pairs at $\varepsilon$ = 8/255, against 20.6\% for our surrogate.


4. \textbf{Architecture matters more than training data.} Models sharing the InceptionResnetV1 architecture fool each other well even with different training faces, while ArcFace resists every attacker (at most 18.8\%, and only at a visible $\varepsilon$ = 16/255). The surrogate-only result that seemed to favour training data (Section 6) does not generalise.


5. \textbf{The effect comes from the optimisation.} Random noise of the same size, JPEG compression and mild blur do almost nothing to the deep models.


6. \textbf{Implication for privacy tools.} Protection built against one recognition system is unreliable against an unknown one: it depends on the tool's choice of model, it is much weaker against a different architecture, and at a nearly invisible budget ($\varepsilon$ = 4/255) even the best pairing transfers to only 27.1\% of pairs.


\needspace{8\baselineskip}\section{Limitations and next steps}

\begin{itemize}
  \item  One editing method (PGD) and one budget sweep. Attacking an ensemble of models at once, the standard way to make edits transfer better, was not tried.
  \item  Seeds 1 and 2 were run with the surrogate as attacker only; the other attackers use seed 0. Seed spread for the surrogate is under 0.7 points, so this is unlikely to matter.
  \item  The saved surrogate is the best epoch on 500 held-out CASIA identities (98.28\% clean LFW). Why it is a weak attacker (overfitting, crop geometry, training budget) is untested; retraining with a box crop would test one of those.
  \item  The original seed-0 sweep scored ArcFace with onnxruntime; all later runs use the PyTorch conversion. Both give identical clean accuracy, and ArcFace's numbers agree across the three seeds to within 0.06 points.
  \item  Face landmarks come from the clean photo and are reused for its edited versions; a real system would re-detect the face, which large edits could shift.
  \item  The proposal's optional check of whether protection holds equally across demographic groups (LFW is roughly 77.5\% male and 83.5\% White) has not been done yet.
  \item  LBPH's low clean accuracy limits what its numbers can show (Section 10).
  \item  PGD's random start adds noise to the whole photo, but only pixels inside the attacker's crop are then optimised, so the noise outside the crop stays (Section 9.3). It slightly lowers SSIM equally for every attacker; starting from the clean photo, or masking the start to the crop, would remove it.
\end{itemize}
